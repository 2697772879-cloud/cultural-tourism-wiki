# 页面规范（Schema）

## 1. 分类法

| type | 目录 | 判别标准 | 举例 |
|---|---|---|---|
| `entity` | `pages/entities/` | 有名称的机构、物件、地点、概念载体 | 香山银行、风水古井、石岐、侨批 |
| `event` | `pages/events/` | 有明确时间点的发生事项 | 1948年重建开业、1997年修缮工程 |
| `building` | `pages/buildings/` | 建筑本体或其构件 | 钟楼、骑楼外立面、青砖墙、雕花楼梯 |
| `person` | `pages/people/` | 具体人物 | 郭泗泉、李德联 |
| `topic` | `pages/topics/` | 跨实体的主题、工艺、制度、价格体系 | 修缮工艺、客房定价、侨商网络 |

**判别优先级**：能归入 `building` / `person` / `event` 的，不进 `entity`；`entity` 与 `topic` 区分不清时，若它是「一个东西」→ entity，是「一类做法/一套机制」→ topic。

一份资料常常同时命中多类：**主体建一页，其余以关联条目或一节带过，并在相关页面各补一句交叉引用。**

## 2. 文件命名

- 中文文件名可用，但**禁止空格和 `\/:*?"<>|`**，空格用 `-` 代替。
- 同一条目只对应一个文件；改名 = 建新文件 + 删旧文件 + 全库改链（代价高，命名前先想清楚）。
- 人物页用全名；建筑构件页用「主体-构件」（如 `钟楼-顶部.md`）；事件页用「年份+事件」（如 `1948-重建开业.md`）。
- 原名已被占用的近似条目，先考虑合并，见 `ingest-workflow.md`。

## 3. Frontmatter 字段

```yaml
---
title: 钟楼
type: building
tags: [钟楼, 青砖, 骑楼, 石岐]
status: draft            # draft | reviewed；人工复核通过后改 reviewed
confidence: medium       # high | medium | low；证据强度
aliases: [思豪钟楼, 大钟楼]   # 用于去重与链接解析
sources:
  - raw/images/20260917-103000-思豪大酒店钟楼.jpg
  - raw/texts/20260917-104500-思豪沿革.md
created: 2026-09-17
updated: 2026-09-17
---
```

必填：`title` `type` `tags` `status` `confidence` `sources` `created` `updated`
可选：`aliases` `location` `period`（年代区间，如 `1920s-1948`）`related`

`status` 与 `confidence` 是给 Dify 检索和人工复核排序用的：低置信页面在问答里应降权或附「待考」提示。

## 4. 页面骨架

```markdown
# 标题

## 摘要
一句话。index.md 会抓这一节的第一段。

## 事实底座
> 本页全部内容的唯一证据来源。先写这里，再写正文和视角；视角不得超出本清单的范围。

- 事实一（原文细节照抄） <!-- src: raw/images/xxx.jpg -->
- 事实二 <!-- src: raw/texts/xxx.md --> `[需人工复核]`

## 正文
分点或分段展开。保留全部细节：年代、地址、人名、构件、尺寸、价格、引文。

## 多视角解读
### 儿童视角
### 历史视角
### 专家视角

## 图片
![西立面全景](https://.../xxx.jpg)   <!-- 仅在有可用图片 URL 时保留此节 -->

## 关联条目
- [[思豪大酒店]]
- [[骑楼外立面]]

## 原始资料
- raw/images/20260917-103000-思豪大酒店钟楼.jpg（用户上传，2026-09-17）

## 修订记录
- 2026-09-17 创建，来源 raw/images/xxx.jpg
```

无图片的页面删掉 `## 图片` 整节，不要留空节。

## 5. 溯源纪律

- 每条事实后用 HTML 注释挂来源：**`<!-- src: raw/texts/20260917-104500-思豪沿革.md -->`**。不渲染、不干扰阅读、可被脚本和检索抓取。
- 一段话糅合多份资料时，逐句挂锚点，不要整段只挂一个。
- **推断与事实分离**：凡属 LLM 推理、常识补全、跨资料拼接得出的结论，必须写进 `## 事实底座` 下方的「推断」子列表并标 `[推断]`，不得混进事实清单。
- **冲突**：新资料与既有说法矛盾时，两边都保留，各自挂来源，并在页面顶部加：

```markdown
> ⚠️ 冲突：本页存在互相矛盾的说法，见「事实底座」第 2、5 条。[需人工复核]
```

同时在 `log.md` 记 `[需人工复核]`。**不擅自裁决、不删旧说法。**

## 6. 图片引用

- Wiki 页面里用 `![描述](URL)`；URL 优先用 Dify 内置文件服务产出的地址，其次为对象存储。
- 单张 < 2MB（Dify 限制），JPG/PNG。原图超限时先压缩（长边 ≤1600px、100–350KB）再上传。
- 原图始终保留在 `raw/images/`，即使页面用的是压缩后 URL。
- 图片说明描述画面内容而非文件名，便于视觉检索命中。

## 7. 链接

- 用 `[[页面标题]]` 或 `[[页面标题|显示名]]`，标题取 frontmatter 的 `title`，或 `aliases` 中的任一别名。
- 首次提到某个已有条目时就加链接，不要只在「关联条目」里补。
- 断链由 `wiki_lint.py` 检查，每次 ingest 后跑一遍。
