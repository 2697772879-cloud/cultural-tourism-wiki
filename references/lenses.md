# 多视角生成规范（Lenses）

## 0. 铁律：先底座，后视角

三视角**必须**从同一个 `## 事实底座` 生成。生成顺序：

1. 写事实底座（已完成）
2. 写正文
3. 写儿童视角 → 历史视角 → 专家视角（固定顺序，便于 diff 与复核）

视角里出现的每一个具体事实（年代、人名、数字、构件名），都要能在底座里逐条对上。**底座没有的，视角里也不能有。** 若为了讲清楚必须补充背景，那属于「常识性解释」（如解释什么是骑楼），可以写，但必须与控制变量区分开，且不得编造本项目专属事实。

## 1. 通用要求

| 项 | 要求 |
|---|---|
| 人称 | 由 `_config.md` 的 `persona` 决定，默认「思豪大酒店专属文史导游」 |
| 独立性 | 每视角自成一体，读者只看其中一个也能读懂，不依赖其他视角 |
| 冲突 | 三视角之间不得出现事实冲突；同一数字在三处必须一致 |
| 复核 | 视角中引用到 `[需人工复核]` 的事实，末尾加一句柔和提示，儿童视角用「据说」等软化词 |
| 图片 | 儿童视角优先配图；专家视角配图用于佐证细节；历史视角按需 |

## 2. 儿童视角（child）

- **语气**：温柔、有趣、亲切，像蹲下来跟小朋友说话。
- **用词**：简单直白，不出现专业术语；必须用术语时立刻打比方（"骑楼，就像房子戴了一顶宽宽的帽子，下雨天走在下面也不会淋湿"）。
- **结构**：**不超过 3 个要点**，每点一两句话。
- **长度**：150–300 字。
- **开头**：`小朋友，你好呀！下面为你讲讲……`
- **禁忌**：不写年代数字堆砌、不写血腥/灾难细节、不写争议性结论、不用反问句连环追问。

## 3. 历史视角（history）

- **语气**：严谨、叙事、有考据感，像一位做过功课的讲解员。
- **内容**：时代背景 → 发展脉络 → 关键人与事 → 后续影响。可引用年代、人物、事件、典故。
- **结构**：分点清晰，可按时间线或因果链组织。
- **长度**：400–800 字。
- **开头**：`你好，我是{persona}，下面为你从历史角度解答：`
- **要求**：涉及因果时说明依据；不确定处明说「一说……，另一说……」，不硬下结论。

## 4. 专家视角（expert）

- **语气**：专业、深入、逻辑严密。
- **内容**：原理 / 工艺 / 材料 / 结构 / 制度逻辑，含技术细节、判定依据、边界与局限、常见误判。
- **结构**：规范论证，可用小标题或编号；能上数据就上数据（尺寸、年代区间、材料规格、文献出处）。
- **长度**：500–1000 字。
- **开头**：`你好，我是{persona}，下面为你提供专业分析：`
- **要求**：必须包含一段**边界说明**——哪些结论证据充分、哪些只是推测、还缺什么材料才能定论。这段是专家视角的价值核心，不可省略。

## 5. 一致性自检（写完立即过一遍）

- [ ] 三个视角里的年代、人名、数字完全一致
- [ ] 没有出现底座之外的事实
- [ ] 儿童视角 ≤3 个要点、无术语堆砌
- [ ] 历史视角有明确时间或因果脉络
- [ ] 专家视角含边界/局限说明
- [ ] 涉及 `[需人工复核]` 的内容已做柔化或标注
- [ ] 三视角开头话术符合规范

## 6. 只重写视角（`/wiki lens`）

当用户只要某个视角，或某个视角写得不满意：

1. 只读该页的 `## 事实底座` 与 `## 正文`。
2. **只替换对应的 `### XX视角` 章节，其余一字不动。**
3. 更新 frontmatter 的 `updated`，并在 `## 修订记录` 追加一行。
4. `log.md` 记：`- [时间] 重写视角：<页面>，视角：儿童，原因：<用户要求>`

## 7. 视角集合可配置

`_config.md` 里可改 `lenses`。例如亲子导览项目可加 `长者视角`，研学项目可加 `研学任务`。新增视角必须在 `references/lenses.md` 补规范，或直接写进 `wiki/_config.md` 的「自定义视角」节。默认三视角为 `儿童 / 历史 / 专家`。
