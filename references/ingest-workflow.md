# 摄取工作流（Ingest）

## 0. 前置

- `wiki/` 不存在 → 先跑 `wiki_init.py`。
- 每次 ingest **只处理一份资料**（一份资料可含多张图）。批量时用第 6 节策略。
- 开始前先读 `wiki/index.md` 全量，把现有条目标题 + 别名在脑子里建索引——这是避免重复建页的关键。

## 1. 落盘

| 类型 | 落点 | 命名 |
|---|---|---|
| 图片 | `raw/images/` | `YYYYMMDD-HHMMSS-简短描述.jpg` |
| 粘贴文本 | `raw/texts/` | `YYYYMMDD-HHMMSS-简短标题.md` |
| PDF / 网页 | `raw/files/` | `YYYYMMDD-HHMMSS-标题.pdf` / `.html` |
| OCR 结果 | `raw/texts/` | `YYYYMMDD-HHMMSS-<原图名>-ocr.md` |

描述用中文，不含空格和特殊字符，长度 ≤ 20 字。原文件名保留在正文首行，便于回溯：

```markdown
> 原文件名：思豪大酒店钟楼.jpg ｜ 用户上传 ｜ 2026-09-17 10:30
```

落盘后立刻写日志：

```markdown
## [2026-09-17 10:30] ingest | 思豪大酒店钟楼.jpg
- 落盘：raw/images/20260917-103000-思豪大酒店钟楼.jpg（图片，用户上传）
- 摘要：钟楼西立面，青砖外墙，顶部四面钟，招牌「思豪大酒店」。
- 新建：pages/buildings/钟楼.md
- 更新：pages/entities/思豪大酒店.md、pages/topics/骑楼.md
- 视角：3（儿童/历史/专家）
- 复核：招牌年份 OCR 不确定 [需人工复核]
```

日志条目的 `## [时间] 类型 | 标题` 前缀是固定格式，便于 `grep "^## \[" log.md | tail -5` 解析。

## 2. 识别与提取

**图片**

1. 视觉模型 / OCR 提取文字（招牌、碑刻、说明牌、手写批注）。
2. 建筑实拍：识别特征——结构形式（骑楼 / 钟楼 / 碉楼 / 庭院）、材料（青砖 / 红砖 / 水刷石 / 木构）、构件（拱券 / 柱式 / 雕花楼梯 / 满洲窗 / 灰塑）、现状（修缮痕迹 / 风化 / 加建）。
3. 输出 OCR 文本到 `raw/texts/`，并在其中标注置信度：识别不清的字写 `□`，整段不确定就标 `[需人工复核]`。
4. 老照片额外记录：拍摄角度、可见招牌文字、人物衣着、街景旁证——这些常是断代依据。

**文本**

清洗（去页眉页脚、统一全半角、修断行）→ 分段 → 输出「原始内容摘要」：

```markdown
### 原始内容摘要
- 核心主题：
- 时间：
- 地点：
- 人物：
- 事件：
- 候选页面：[building] 钟楼 / [person] 郭泗泉 / [topic] 修缮工艺
- 存疑点：
```

## 3. 新建 or 合并：决策树

```
查 index.md + 全库 title/aliases
│
├─ 有同名或同别名条目？
│   ├─ 是 ── 指向同一对象？ ── 是 → 合并（默认）
│   │                         └─ 否 → 建新页 + 在旧页加「易混淆」说明 + 双向链接
│   └─ 否 ── 有语义近似条目（如同建筑的构件、同一事件的不同年份）？
│             ├─ 是 → 若信息量小，合并进父页并加小节；若足以独立成页 → 建子页并双向链接
│             └─ 否 → 新建
```

**合并时的操作**（不是简单追加）：

1. 新事实并入 `## 事实底座`，带新 `src` 锚点。
2. **修订** `## 摘要`（旧摘要可能已不准确）。
3. 正文去重：与既有内容重复的信息不重复写；措辞不同但事实相同的，保留更精确的那条。
4. 追加 `sources`、更新 `updated`、追加 `## 修订记录`。
5. **重新生成三视角**——事实底座变了，视角必须跟着变，不能只改正文。
6. 冲突按 `schema.md` 第 5 节处理。

## 4. 一次摄取要动多少页面

一份资料通常影响 5–15 个页面。收工前逐项确认：

- [ ] 主体页面（新建或合并）
- [ ] 被提及的既有实体/人物/建筑页：各补一句交叉引用或新事实
- [ ] 相关主题页（工艺、制度、价格体系）
- [ ] 时间线相关事件页
- [ ] 全库反向链接：新建页面后，被它引用的页面应补上反向链接或至少出现在对方的关联条目里
- [ ] `index.md`（用脚本重建）
- [ ] `log.md`（手写追加）

## 5. 幂等

- 落盘前算内容哈希，与 `log.md` 中已记录的哈希比对（写入 `raw/` 同目录的 `.manifest.tsv`：路径 / 哈希 / 摄取时间）。
- 命中已摄取 → 回复「该资料已于 X 时间摄取，涉及的页面为……，是否需要重新处理？」，不重复建页。

## 6. 批量处理

1. **先列清单**：把待处理资料全部落盘 + 写日志，不急着生成。
2. **轻量初筛**：用摘要级处理产出「原始内容摘要」和分类建议，让用户过目。
3. **再精加工**：用户确认后，逐份生成完整页面与三视角。
4. **分批**：每批 5–10 份，批间跑一次 `wiki_lint.py`。
5. 批量时**降低视角长度**（儿童 100 字 / 历史 300 字 / 专家 400 字），保证速度与成本；重点条目后续单独精修。

## 7. 收尾报告（必须输出）

```markdown
### 摄取报告
- 原始资料：raw/images/xxx.jpg（图片，用户上传）
- 新建页面：pages/buildings/钟楼.md
- 更新页面：pages/entities/思豪大酒店.md、pages/topics/骑楼.md（共 2 个）
- 生成视角：3 组（儿童 / 历史 / 专家）
- 需人工复核：招牌年份 OCR 不确定（钟楼.md 事实底座第 3 条）
- 下一步：补充《1948年重建开业》事件页；跑一次 /wiki lint
```
